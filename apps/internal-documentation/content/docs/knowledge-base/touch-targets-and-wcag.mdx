# Touch targets and WCAG

A reference for the accessibility and responsive-design rules that
the marketing pages apply. Sources, current standards (2026), and
the conventions we ship.

> **Scope note.** The Knowledge Base is reserved for studies of
> external libraries the codebase depends on (see ADR-016,
> ADR-017). This entry is a transverse reference for accessibility
> standards, not a library study. It lives here because the
> marketing-site surface is the largest consumer of the rules and
> needs a single place to look them up. Treat it as a reference
> doc, not as a precedent for the KB structure.

## The three minimums you must know

| Standard | Source | Minimum | What it counts |
|---|---|---|---|
| **WCAG 2.5.8** (Level AA, WCAG 2.2) | [W3C](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 24×24 CSS px | The full interactive bounding box |
| **Apple HIG** | Apple developer docs | 44×44 pt | Hit area |
| **Material Design 3** | Google M3 spec | 48×48 dp | Hit area |

WCAG 2.5.8 has an **8px-spacing exception**: if adjacent targets
have at least 8 CSS px of spacing between them, the minimum drops
back to 24×24. Without the spacing, the minimum stays at 24×24
strict.

## What DeesseJS ships

Primary CTAs on the marketing surface target **48px minimum
height** (`min-h-12` in Tailwind). The reasoning:

- 48px is **above all three minimums** simultaneously
  (WCAG AA, Apple HIG, Material).
- It is below the visual ceiling that would feel oversized on
  a desktop hero.
- It is the default height Material components ship with, so
  the codebase already renders correctly at this size in many
  inherited places.

Secondary buttons (variant="outline" inside a card, "Email us"
in the footer CTA) inherit the same `min-h-12` from the same
component. We do not differentiate by variant for height; we
differentiate by **fill weight** (default vs outline), not by
size.

## What the research says

The [NN/g study on touch targets](https://www.nngroup.com/articles/touch-target-size/)
cites the MIT Touch Lab measurement of average fingertips
(1.6-2cm wide) and thumb impact areas (~2.5cm). Even the
1cm-physical minimum they propose is well below actual finger
size. The practical conclusion:

- **Primary CTA**: 48px+ height, no exception.
- **Adjacent secondary targets**: 8px+ spacing between them.
- **Icon-only buttons**: keep the icon visually small
  (16-20px) but expand the hit area with `padding` to reach
  48×48. Never rely on icon size alone.

[web.dev's tap-targets guide](https://web.dev/articles/accessible-tap-targets)
notes the same 48px target with 8px spacing, and adds a useful
detection tip: use `@media (any-pointer: coarse)` to enlarge
targets for any touchscreen user regardless of device class.

## Pricing-page patterns we follow

Three patterns exist for mobile pricing tables:

| Pattern | When | Trade-off |
|---|---|---|
| **Vertical stacked cards** | Default. Use unless you have a reason not to. | Comparison requires scroll-back. Universally accessible. |
| **Horizontal scroll with peek** | 3-4 plans, direct comparison matters. | Needs an explicit swipe affordance. |
| **Accordion per tier** | Long feature lists, many add-ons. | Hidden content lowers conversion. Extra tap friction. |

The pricing page at `/pricing` uses vertical stacked cards on
`<md` and a horizontal-scroll comparison table on `<sm` (returning
to a flat table at `sm+`). Both are the dominant 2026 convention
(Stripe, Linear, Vercel).

## Specific responsive rules the page applies

These are the rules the pricing page follows after the responsive
audit. Other marketing pages can copy them.

| Rule | Where | Tailwind |
|---|---|---|
| Primary CTA buttons reach 48px height | `LayerCard` CTA, footer CTA | `min-h-12` |
| Trust band mono stays readable in narrow viewports | Trust band under the cards | `text-left sm:text-center sm:text-copy-14-mono` |
| Persona card bodies align in height in `md:grid-cols-2` | Personas block | `line-clamp-4` on the body `<p>` |
| Comparison table scrolls horizontally on `<sm` | "Side by side" section | `overflow-x-auto` + `min-w-[640px]` on the `<table>` |
| Article wrapper breathes at every breakpoint | Outer `<article>` | `px-4 sm:px-6` + `gap-16 lg:gap-20` |
| Long headings wrap evenly | All `h1` / `h2` | `text-balance` |

## What this reference allows

- Adding `min-h-12` to a primary CTA is the default fix when a
  page audit flags a touch-target undersize.
- Adding `line-clamp-N` to balance heterogeneous card heights
  inside a `grid-cols-N md:grid-cols-M` layout.
- Centering dense mono copy at `sm+` while leaving it
  left-aligned on `<sm` to avoid awkward mid-word gaps.

## What this reference does not cover

- Keyboard navigation patterns (Radix primitives cover this).
- Screen-reader semantics beyond what WCAG 2.5.8 enforces
  (`aria-label`, `aria-hidden`, `role`, focus management).
- Color contrast — handled by the design-token layer, not by
  per-page code.
- Reduced-motion (`prefers-reduced-motion`) — Motion components
  in the homepage Contracts grid respect it; pricing has no
  motion today.
