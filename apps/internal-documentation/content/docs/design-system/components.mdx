# Components

`@workspace/ui` is the only product-UI surface in the monorepo. It ships 26 primitives today, all from the shadcn `radix-nova` distribution plus a custom `Typography` block. The package does not wrap shadcn behind a domain layer; what you see in `packages/ui/src/components/` is what you consume.

See [ADR-020](./decisions/ADR-020) §1 (single surface) and §6 (primitive policy) for the locks.

## What is not a primitive

The package deliberately does not ship:

- A `Form` field-plus-label-plus-error primitive. Forms use `react-hook-form` + `Zod` as a pattern (see `DESIGN.md` §4.2). shadcn's CLI `Form` registry entry is not used; the pattern lives in app code or in a future `@workspace/forms` package.
- A wrapper around shadcn's `Empty`, `Item`, `Spinner`. shadcn ships these as v0.1-deferred primitives (see `DESIGN.md` §7); they are added through the §8 procedure when an app has a use case.
- An icon wrapper. Components reach into `lucide-react` directly. See below.

## Icons

The icon library is `lucide-react`. Each component that needs an icon imports the named icon directly:

```tsx
import { XIcon, ChevronDownIcon } from "lucide-react"
```

There is no `<Icon name="x" />` indirection. Swap of the icon library requires a new ADR; the lock is in [ADR-020](./decisions/ADR-020) §3.

## Conventions baked into the primitives

The primitives follow five conventions that the app code inherits by extension.

| Convention | Where it shows |
|---|---|
| `data-slot="..."` attributes | Every primitive carries `data-slot`. Tailwind targeting and test selectors use them. |
| `cva` + `VariantProps<typeof variants>` | `Button`, `Badge`, `Tabs`, `InputGroup`, `NavigationMenu`, `Sidebar` use `class-variance-authority`. Variant values are lowercase strings. |
| `asChild` + `Slot.Root` | Any primitive that wraps an existing element (link styled as button, button inside a form) accepts `asChild` and uses `Slot.Root` from `radix-ui`. |
| `"use client"` only when needed | 18 of 27 files carry the directive — every component that touches React state, refs, effects, Radix context, or `useTheme`. The other 8 stay server-friendly. |
| Kebab-case filenames, PascalCase exports | File names use kebab-case (`dropdown-menu.tsx`, `input-group.tsx`); component identifiers and the directory `components/` use PascalCase. |

## Adding a primitive

The add procedure is `DESIGN.md` §8 + [ADR-020](./decisions/ADR-020) §6 condensed:

1. `pnpm dlx shadcn@latest add <name>` lands the source in `packages/ui/src/components/<name>.tsx`.
2. Read the generated source. Adjust variants, states, dark-mode wiring to match the conventions in this page.
3. Add a row to the inventory in this page (and to `DESIGN.md` §7) in the same PR.
4. Verify dark mode, `prefers-reduced-motion`, keyboard navigation.
5. Run `pnpm typecheck` and `pnpm build`; both stay green across the workspace.

There is no gate beyond "app needed it". A primitive without a consumer is the senior anti-pattern (`DESIGN.md` §1.5).

## Removing a primitive

The remove procedure is `DESIGN.md` §9 + [ADR-020](./decisions/ADR-020) §6 condensed:

1. `rm packages/ui/src/components/<name>.tsx`.
2. Remove imports across the codebase (`rg "@workspace/ui/components/<name>" apps/`).
3. `pnpm typecheck` must remain green.
4. `pnpm build` must succeed.
5. Remove the row from the inventory in this page (and from `DESIGN.md` §7) in the same PR.

Removing a primitive a buyer app needs is a breaking change. Surface it in the PR description.

## Bypassing a primitive

One bypass exists today and is documented: `apps/web/src/components/knowledge-base/badges.tsx` does not import `Badge` from `@workspace/ui/components/badge`. The file's leading comment names the reason: the shadcn `Badge` variants are too generic for the knowledge-base styling needs, and the file wants full colour control. The rule is to **preserve the comment on every edit**. Removing the comment is a review-reject.

Other bypasses, if needed, follow the same shape: a leading comment in the file, naming the reason and pointing at the design-system alternative being bypassed.

## What the package does not own

Domain components. There is no `<UserAvatar>`, `<ProjectCard>`, `<PlanBadge>` in `packages/ui`. Those live in the consuming app — they compose primitives, they do not add to the design system. A component that needs a domain shape belongs to the app that uses it.

Marketing chrome. `apps/web/src/components/headers/`, `footers/`, `blog/`, `templates/` are app-local compositions of primitives. They are not part of `@workspace/ui`.
