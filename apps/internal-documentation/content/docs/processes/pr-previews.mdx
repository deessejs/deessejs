# PR previews

Every push to a PR that touches CLI-relevant paths rebuilds `@deessejs/cli` and uploads a tarball to pkg.pr.new. Reviewers can install the preview with the URL posted as a sticky comment on the PR. The tarball lives on pkg.pr.new's infrastructure (Cloudflare R2), not on npmjs.org.

This is **Tier 1** of the three-tier release pipeline defined in [ADR-021](../decisions/ADR-021-cli-three-tier-release.mdx). It is a separate workflow from `release.yml` because pkg.pr.new authenticates via its own GitHub App, not via OIDC to npm.

## When this process applies

- A contributor opens a PR that changes CLI-relevant paths.
- A reviewer or consumer needs an installable preview before approval.
- A new push to an existing PR (preview rebuilds with the latest commit, idempotent).

## Prerequisites

- The pkg.pr.new GitHub App is installed on `deessejs/deessejs`.
- The PR targets `staging` or `main`.
- The PR changes at least one of the trigger paths below.

## Triggers

`.github/workflows/cli-preview.yml` runs on every `pull_request` against `staging` or `main`, but only when the PR touches one of the following paths:

```yaml
paths:
  - "apps/cli/**"
  - "packages/contracts/**"
  - "packages/api/**"
  - ".github/workflows/cli-preview.yml"
  - "pnpm-lock.yaml"
```

The `pnpm-lock.yaml` entry matters: a catalog bump that changes effective CLI output must trigger a new preview even when no source file under `apps/cli/**` changed.

## Procedure

### 1. Concurrency: idempotent per PR

The job uses a concurrency group keyed on the PR number with `cancel-in-progress: true`:

```yaml
concurrency:
  group: pkg-pr-new-${{ github.event.pull_request.number }}
  cancel-in-progress: true
```

A new push to the PR cancels the previous preview build and replaces it. Previews are therefore idempotent per PR: only the latest commit is reflected in the install address.

### 2. Build scope

The job builds the CLI and its transitive workspace deps in topological order. Tests and lint are deliberately not run here:

```bash
pnpm turbo build --filter=@deessejs/cli
```

Tests and lint are covered by `ci.yml`. The publish path runs `cli-publish-verify.yml` separately on PRs that touch release-config files. Skipping them in the preview keeps the per-PR feedback loop fast.

### 3. Upload the tarball

```bash
pnpm exec pkg-pr-new publish ./apps/cli --pnpm --compact --bin --comment=off --json output.json
```

Flags rationale:

- `--pnpm` is required because the workspace uses pnpm catalogs.
- `--compact` shortens the install URL.
- `--bin` renders `npx ...` form in the PR comment instead of `npm i ...`.
- `--comment=off` disables pkg-pr.new's default sticky comment so this workflow can post its own richer one (four package managers, link to commit, stable marker).
- `--json output.json` feeds the comment-posting step.

### 4. Post or update the sticky PR comment

After upload, the workflow posts or updates a sticky PR comment with the marker `<!-- pkg-pr.new -->`. The marker lets the workflow detect a prior comment from an earlier push on the same PR and edit it in place instead of creating a new one. The body contains install instructions for `pnpm` (open by default), `npm`, `yarn`, `bun`, plus a link to the commit.

A reader who sees a comment without the marker can conclude it is stale and not authored by this workflow.

## Artefacts

- A tarball uploaded to pkg.pr.new (Cloudflare R2), addressed by commit SHA.
- A sticky PR comment with install instructions for `pnpm`, `npm`, `yarn`, `bun`.

## Security boundary

The workflow runs with `contents: read` and `pull-requests: write`. It does **not** request `id-token: write`. pkg.pr.new authenticates via its own GitHub App, separate from npm Trusted Publishing. A compromise of this workflow's secrets cannot affect the `@latest` or `@canary` release paths.

## Retention

Previews live on pkg.pr.new's infrastructure (Cloudflare R2), not on npm. Retention is best-effort: roughly one month without a download, or six months of age, whichever comes first. The repository has no operational control over deletion.

## Recovery

**Stale preview comment on a PR:** the comment was not updated after the latest push. The most likely cause is a `<!-- pkg-pr.new -->` comment that was authored by a fork contributor (the bot does not run with `pull-requests: write` on forks). Close and re-open the PR, or have a maintainer push a follow-up commit to retrigger the workflow.

**Preview workflow fails on pkg.pr.new unreachable:** pkg.pr.new's infrastructure is third-party. The CLI release path is unaffected (no shared auth, no shared secret). Retry once, and if it persists, document the gap in the PR review and rely on `ci.yml` + `cli-publish-verify.yml` for the gate.

**pkg-pr-new app not installed on the repo:** the workflow fails with a permission error. Install the GitHub App on `deessejs/deessejs` settings, then push a follow-up commit to retrigger.
