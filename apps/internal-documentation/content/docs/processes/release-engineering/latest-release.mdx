# Latest release

This process covers shipping `@deessejs/cli` from a merged PR on `staging` to a tagged release on `main`. The `@latest` channel is the canonical release path. It runs automatically on push to `main`; the human gate lives at PR-approval time, not at promotion time. Two auxiliary channels (`@canary`, per-PR previews) live in their own pages.

## When this process applies

- A PR touching `apps/cli/**`, `packages/contracts/**`, or `packages/api/**` has been merged to `staging`.
- The merge commit message contains `.changeset` (enforced by `changesets-check.yml` as a required status check on branch protection).
- Branch protection on `main` passes: CI is green, the changeset check is green, and at least one approving code review is recorded.

## Prerequisites

- Branch `staging` carries the work to ship.
- The contributor added a `.changeset/<slug>.md` file if their PR touched CLI-relevant paths. The `changesets-check.yml` workflow enforces this as a required status check on `staging` and `main` (see [ADR-026](../../decisions/ADR-026-changesets-merge-gate.mdx)).
- The npm Trusted Publisher is configured for `@deessejs/cli` on `https://www.npmjs.com/package/@deessejs/cli/access` against `.github/workflows/release.yml`.
- `NPM_CONFIG_PROVENANCE=true` is available to GitHub Actions via OIDC.

## Procedure

### 1. The merge to staging auto-propagates to main

Once a feature PR lands on `staging` with green CI and a green changesets-check, the branch-protection rules on `staging` and `main` together propagate the work. A human does not run `gh pr create --base main` or click any merge button for `main`. The release is the natural consequence of the feature PR's approval.

The two branch protections enforce:

- **On `staging`**: required checks `ci` and `check-changeset`, plus an approving code review.
- **On `main`**: required checks `ci` and `check-changeset` against the propagated commit.

A merge to `staging` that lands a commit with `.changeset` in the message reaches `main` through the standard propagation flow. `release.yml` then runs.

### 2. Verify the release workflow runs

`.github/workflows/release.yml` triggers on push to `main` when the commit message contains `.changeset`. The job does, in order:

```bash
pnpm install --frozen-lockfile
pnpm changeset version           # bumps apps/cli/package.json#version, regenerates CHANGELOG.md, deletes consumed .changeset/*.md
pnpm changeset publish --provenance --access public
git tag -f release/v{VERSION}
gh release create release/v{VERSION} --generate-notes
```

`{VERSION}` is read from `apps/cli/package.json#version` after step 2.

### 3. Verify artefacts

After the workflow completes:

- `npm view @deessejs/cli@latest version` returns the new version.
- The `release/v{VERSION}` tag is present on the merge commit.
- A GitHub Release exists with autogenerated notes.
- `apps/cli/CHANGELOG.md` lists the new entry at the top.

## Artefacts

- A new `@deessejs/cli` version on npm with provenance attestation.
- A `release/v{VERSION}` git tag on the merge commit.
- A GitHub Release with autogenerated notes.
- An updated `apps/cli/CHANGELOG.md`.

## Recovery

**Provenance rejected (403 from npm):** the Trusted Publisher is not configured. Open `https://www.npmjs.com/package/@deessejs/cli/access` and complete the OIDC configuration, then re-run the workflow.

**Lockfile drift:** `pnpm install --frozen-lockfile` fails. Run `pnpm install` locally, commit the lockfile change, and re-trigger the workflow.

**`apps/cli/package.json#private: true` left in place:** changesets refuses to publish. Verify the field is `false` before re-running.

**Workflow misbehaves and a release must still go out today:** use the [manual fallback](../../../../../documents/internal/process/release-engineering.md#manual-fallback) — publish from a maintainer machine, accept the loss of provenance for that one release, and file an issue to repair `release.yml`.

**Within 72 hours of a bad publish:** `npm unpublish @deessejs/cli@x.y.z` removes the version entirely.

**After 72 hours:** `npm unpublish` is no longer allowed. Use `npm deprecate @deessejs/cli@x.y.z "Critical bug: see <link> — upgrade to x.y.z+1"` and record the yank in the next release notes.

**Commit message on main is missing `.changeset`:** the workflow's `if:` filter rejects the run; no release happens. Re-run with the correct message, or push a follow-up commit whose message contains the token. Branch protection makes this rare but not impossible (force-pushes bypass protection rules).
