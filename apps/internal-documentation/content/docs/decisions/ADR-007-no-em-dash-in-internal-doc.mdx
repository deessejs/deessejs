# ADR-007: No em dash in the internal-documentation site

## Status

Accepted (2026-08). Non-negotiable.

## Context

The em dash (. ) is a typographic mark that AI tools emit
constantly. In the rendering site, every em dash is a tell
that the prose did not come from a human writer. The site
is supposed to read as the project's voice; the em dash
breaks that voice.

The em dash is not banned in the source `docs/engineering/`
tree. The rules and ADRs are written by humans and edited
by humans; the em dash is a stylistic choice the author
makes. The rule in this ADR is **for the rendering site
only** , the `apps/internal-documentation/content/docs/`
directory.

## Decision

The rendering site uses no em dash. Two replacements are
valid:

- **A comma** , for a parenthetical aside that the reader
  can skip.
- **A period** , for a full clause break that the reader
  should pause on.

The choice is the author's; the only rule is **no em dash**.

A single line of MDX containing an em dash is rejected in
review. The contributor replaces the em dash with the
chosen alternative and explains the choice in the diff if
the alternative is not obvious.

## Why

The em dash is the AI writing signature. The upstream docs
that the rendering site is built from are written by
humans, and the prose reads as the project's voice. A
single em dash in a paragraph reads as a tone break: the
reader registers it, consciously or not, and the trust
between the author and the reader erodes.

The rule is **not** about the em dash itself. The em dash
is a fine typographic mark. It is about the signature. The
site reads as the project's voice when the prose is the
project's prose; the em dash is the AI's, not the project's.

The rule is also **not** about other AI tells. Those are
subjective, library-by-library, and frequently updated by
the AI tools. The em dash is the durable signal because it
is universal across AI writing as of 2026. We add more
rules as more signals become durable.

## What this rule allows

- **A comma** for the same role an em dash would play.
  "The rule, not the rule's source, is what we follow."
- **A period** for a clause break. Two sentences are
  clearer than one with an em dash.
- **A hyphen** (`-`) for compound adjectives. "The
  no-em-dash rule" is a hyphen, not an em dash.
- **An en dash** (`–`) for ranges. The rule is about the
  em dash, not the en dash.
- **The em dash in source quotes** (a `>` blockquote of
  verbatim text from a rule or an ADR). The source quote
  reproduces the upstream; the em dash stays.

## What this rule forbids

- **An em dash (. ) in the rendering site content.** The
  one and only rule.
- **A lint rule that flags en dashes (`–`) or hyphens
  (`-`)** alongside the em dash. The lint rule is
  scoped to the em dash character only.
- **An em dash in a code block** (the lint ignores
  fenced code blocks). The em dash in code is meaningless
  to the lint and meaningless to the reader; a code
  block is example code, not prose.

## How to enforce

A small lint pass on the rendering site source files.
The pass reads every `.mdx` file in
`apps/internal-documentation/content/docs/`, finds every
em dash character (`. `, U+2014), and reports the file and
line. The pass is a script:

```ts
// apps/internal-documentation/scripts/lint-em-dash.ts
import { readdir } from 'node:fs/promises'
import { readFile } from 'node:fs/promises'
import { join } from 'node:path'

const docsDir = 'content/docs'
const emDash = '. '

for (const file of await readdir(docsDir)) {
  if (!file.endsWith('.mdx')) continue
  const content = await readFile(join(docsDir, file), 'utf8')
  const lines = content.split('\n')
  for (let i = 0; i < lines.length; i++) {
    if (lines[i].includes(emDash)) {
      console.error(`${file}:${i + 1}: em dash found`)
    }
  }
}
```

The script is invoked in CI on every PR that touches the
rendering site. Failures block the PR.

The script is fast , no parsing, no MDX, no file walking
across the repo. It runs in <100ms on the current
content.

## Where this rule came from

The rule came from the second migration to the rendering
site (rule 0001, project mindset). The migration used an
em dash in the epigraph ("the trust-the-type principle").
The em dash was inherited from the source rule's
blockquote. The rendering site showed the em dash
prominently in the layout. The proposer's reaction was
"the AI did this" , and the rule emerged.
