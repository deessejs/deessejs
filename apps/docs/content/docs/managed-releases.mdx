---
title: Managed releases
description: Publish immutable template and block artifacts through the DeesseJS CLI.
---

Managed releases let authorized authors publish template or block snapshots without making source repositories public. The API decides ownership, roles, paid seats, version order, archive validation, and download access.

## Publish a release

Commit a clean Git working tree before publishing. The root descriptor needs a canonical stable version in `MAJOR.MINOR.PATCH` SemVer. Its version must exceed the previous release. The CLI archives files selected by the template's `includes` and `excludes`, or the block's install file list.

```sh
deessejs auth login
deessejs template publish --slug my-template --destination my-organization
deessejs block publish --slug my-block --destination my-organization
```

Set `--destination deessejs` for platform releases. Platform publishing requires an administrator. Organization publishing requires a managing role and an assigned active paid seat under an active qualifying subscription. PR #577 adds the separate version-bump commands.

Publishing and catalog review serve different purposes. Run `deessejs organization template request-listing <organization> <slug> --confirm-distribution-rights` to request public catalog review. This request neither publishes a managed release nor approves a catalog entry.

## List and initialize

Run `deessejs template releases [slug]` to list ready platform releases without exposing storage keys. Add `--organization <organization-slug>` to list private releases you can access.

Run `deessejs init <slug>` to use the source selected by the API. Protected templates require managed releases. Initialize a private organization template with `deessejs init <slug> --organization <organization-slug>`. Add a private block with `deessejs add <block-slug> --target <package-id> --organization <organization-slug>`. Paid templates and blocks require an active Pro seat. Public GitHub templates continue to use their pinned public source.

An unqualified version resolves to the highest ready, non-withdrawn release. If that release gets withdrawn, resolution falls back to the next eligible version. Explicit requests for withdrawn versions return no result. Re-publishing the same version and bytes remains idempotent. Changed bytes require a higher version.

## Storage and limits

Configure two distinct private buckets: `R2_TEMPLATE_RELEASES_STAGING_BUCKET` and `R2_TEMPLATE_RELEASES_BUCKET`. Reuse the existing R2 account and credential variables. The staging bucket needs a lifecycle rule that deletes abandoned uploads after a short period. The API checks archive paths and entry types. It caps compressed archives at 100 MiB and expanded content at 200 MiB. It seals exact bytes under a server-generated key. It returns short-lived download URLs scoped to one artifact.

Templates may declare `previewImage` in `deesse-template.json`. The API stores a Portable Network Graphics (PNG), Joint Photographic Experts Group (JPEG), or WebP image from the validated archive bytes. Without a preview image, the catalog shows its placeholder. Authors have no manual preview upload option.

Local development needs no R2 credentials. API tests use a fake storage adapter. Before production launch, test non-production Cloudflare R2 buckets. Check permissions, signed uploads and downloads, content type, and the staging lifecycle rule.
