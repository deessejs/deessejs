DeesseJS provides a **template registry and starter framework** for teams shipping production-ready apps across web, mobile, edge, and AI. Its curated starters share cross-cutting contracts. DeesseJS doesn't provide a SaaS product, a database mapping library, or a UI library.

## Two Ideas: Surfaces and Contracts

Every DeesseJS template has two defining axes.

A surface describes a template's target platform.

- Web (Next.js, Astro)
- Mobile (Expo, React Native)
- Edge (Cloudflare Workers, Vercel Edge)
- AI agents (Vercel eve, OpenAI-compatible runtimes)
- Desktop (Electron, Tauri)

Contracts cover needs shared across each app.

- Auth (Better Auth with email + GitHub OAuth + device flow)
- Database (drizzle for Postgres)
- Email (Resend in prod, console in dev)
- Storage (S3-compatible)
- Cookies (General Data Protection Regulation (GDPR) consent banner and Zustand store)
- Payments (Stripe via Better Auth)

Each template combines one **surface** with a set of contracts. For example, `next-app-starter` combines `web` with `{auth, database, email, cookies}`. `expo-starter` combines `mobile` with `{auth, database}`. Every template uses the same contract wiring, so the patterns carry across projects.

## DeesseJS at a glance

- A **public registry** of templates you can browse in the CLI and on the web.
- A **published CLI** (`@deessejs/cli`) for scaffolding, browsing, and signing in.
- A **monorepo of contracts**: auth, database, and email packages that version, test, and share across every starter.
- A **device-flow authentication** path that connects the CLI to a web session without storing a password.

## What DeesseJS lacks

- **No bundled framework.** DeesseJS templates use Next.js, Expo, Astro, and similar runtimes. Choose the framework that fits your target surface.
- **No hosting platform.** Templates create project files locally. Deploy them wherever you choose.
- **No database or UI library.** Templates can include third-party dependencies such as drizzle, Tailwind, shadcn/ui, and Better Auth.
- **No lock-in.** Projects created from templates don't depend on DeesseJS services at runtime. Fork a template repository and continue independently.
