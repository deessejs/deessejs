The `@deessejs/cli` package (`deessejs` on npm) helps you discover and scaffold DeesseJS templates, then sign in to use authenticated CLI features. Install the CLI once. Use it to create projects from the templates.

## What the CLI does

- **Browse the registry**: `deessejs list` shows every template, optionally filtered by category.
- **Inspect a template**: `deessejs info <slug>` prints metadata plus the install line.
- **Scaffold a template**: `deessejs init <slug-or-github-url>` uses the repository's `deesse-template.json`, detects the package manager, and installs dependencies.
- **Sign in**: `deessejs auth login` opens the browser for a device-flow approval. The CLI caches the resulting token at `~/.deessejs/auth.json`.

That lists the full public surface. Adding new top-level commands or flags counts as a breaking change and goes through a release-train review.

## Install

```bash
# Use once, no install
npx deessejs@latest init <slug>

# Or install globally
npm install -g @deessejs
deessejs init <slug>
```

The CLI publishes to npm with provenance from its GitHub Actions release workflow. Every npm release ships as stable. The CLI offers no `@canary` or pre-release channel.

## Requirements

- **Node.js 20.0.0 or newer**: declared in `engines`. `npx` and global installs both enforce it.
- **GitHub access**: required by `init` to download the repository archive and read its descriptor.
- **A package manager**: `pnpm`, `npm`, `yarn`, or `bun`. `init` picks one based on the generated project. Override with `--pm <name>`.

## What the CLI doesn't do

- It doesn't host templates. They live in GitHub repositories, and the CLI uses each repository's descriptor to select files.
- It doesn't manage your environment variables. Templates ship `.env.example` files. Copy one and add your values.
- It doesn't deploy. Use your platform's tools to deploy the generated project, such as Vercel, Expo Application Services (EAS), or Cloudflare.
