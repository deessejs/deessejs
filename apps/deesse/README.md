# deesse

Internal, compile-time framework prototype. This package is private and is not production-ready or publishable.

The prototype validates explicit `DeesseConfig` inference, the typed `DeesseInstance` properties, parsed Zod plugin arguments and contributions, readonly root-plugin tuples, app and plugin oRPC router composition, Better Auth server-instance typing for application-configured plugins, the `deesse` and `deesse/react` public type surfaces, and a portable database capability contract that does not expose a provider client. Its type tests check exact router inputs/outputs, valid and invalid client calls, and that an empty API has no procedure keys.

`createDeesse()` currently returns a typed composition record only. It does not initialize services or serve requests; in particular, `auth` is a type-only placeholder and is not a constructed Better Auth instance. Its declared type is derived from Better Auth's `betterAuth<TOptions>` return type, and the tests assert the organization server API method for application-configured auth plugins. Plugin factories parse registration arguments, but do not initialize contributions. Better Auth server-plugin contributions from Deesse plugins are intentionally not part of this prototype's public type contract: Better Auth's inferred server API depends on its mutable plugin-list option, and composing that list from independently inferred application and Deesse plugin tuples did not preserve both plugin-specific endpoint surfaces. The attempted composition preserved the Deesse-contributed username endpoint but erased the application-configured organization endpoint. Supporting this safely needs a separately designed config/type boundary; this prototype does not claim plugin-contributed auth typing or runtime merging. Type tests import the public `deesse` and `deesse/react` specifiers; local TypeScript path mappings resolve them to source because generated build output is intentionally not committed. The client API member is a type placeholder, not a working transport client. The RFC's lifecycle, Hono dispatch, Next host adapter, database implementation, and dependency validation remain out of scope for this slice.
