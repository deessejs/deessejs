# `@workspace/database`

The schema of DeesseJS: the Drizzle tables, the migrations and the database client.

## What's included

- **`db`**: the Drizzle client, lazily connected and tuned for serverless Postgres
- **The schema**: the authentication tables, generated by the Better Auth CLI, and the application tables
- **The migrations**: the SQL files in `drizzle/`, generated by Drizzle Kit
- **The test harness**: pg-mem, so the suite runs without a database

## Usage

```ts
import { db } from "@workspace/database"
import { organization, member } from "@workspace/database/schema"

const rows = await db.select().from(organization)
```

The schema is also passed whole to the Drizzle adapter:

```ts
import { db } from "@workspace/database"
import * as schema from "@workspace/database/schema"

drizzleAdapter(db, { provider: "pg", schema })
```

A table that is not exported from the schema barrel does not exist for the adapter.

## Exports

| Export | Import path | Contents |
|---|---|---|
| `.` | `@workspace/database` | The `db` client and the schema barrel |
| `./schema` | `@workspace/database/schema` | The tables, on their own |

## Commands

```bash
pnpm db:generate   # diff the schema, write a SQL migration
pnpm db:migrate    # apply the pending migrations
pnpm db:push       # sync the schema directly, development only
pnpm db:studio     # open Drizzle Studio
pnpm db:check      # drizzle-kit check
pnpm test          # the pg-mem suite
pnpm test:run
pnpm typecheck
pnpm lint
```

## Notes

- `src/schema/auth.ts` is generated by the Better Auth CLI. Regenerate it with `pnpm auth:generate` from `packages/auth`, and never edit it by hand.
- The application tables go in `src/tables/`, not in the auth schema.
- The pool is created lazily, on the first access to `db`, so a missing `DATABASE_URL` surfaces at that moment rather than at import time.
- The migrations are linted by Squawk, configured in `.squawk.toml` at the root. A waived rule needs a `squawk-ignore` directive next to the statement it applies to.
